# Issue 035 — FA-constrained exact posterior sampling for the dLLM decode lane (POC)

**Status:** OPEN — **P0+P0.5+P1+P2 COMPLETE (2026-10-05/06, the 4090 box): the sampler ships exact and allocation-free (P0 `8223d27`), the O(log L) f64 segment-tree lane + 1e-9-verified marginals (P0.5 `8bd5c2d`), the decode wiring (P1 `304876f`+`f4ffa93`), and the schema front end + overhead bench (P2 `1254264`+`5b5c462` — `src/fa_schema.rs` compiler, 12 tests, `examples/fa_schema_overhead_bench.rs`). **P2.5 LANDED (2026-10-06, the ungated G2 axis): `src/fa_minimize.rs` — language- and distribution-preserving DFA minimization applied in `fa_schema::compile`; the subset bloat collapses 3.4× on nodes / 6.4× on edges (fn-call 1473/5997 → 435/940) and the overhead ratio drops ~4.4× (toy 1.6-2.2× → 0.50-0.64×, object ~22× → ~6.5×, fn-call ~440× → ~96-111×).** P2's honest headline stands for LARGE grammars: the CPU joint draw is O(L·E) — the single-digit-% G2 bar still needs the GPU-side fold (or an emission-fold restructure) at P3.** P3 (GOAT verdict) is owner-gated — the promote/demote call consumes the numbers above.** POC filed from Research 008 (arXiv:2607.07026 / `MhDang/mosaic` distill); consumer = the `gemma2_d2f` denoising decode loop.

## Why

The `dllm` decode path (`riir-infer/src/transformer/dllm.rs` D2F forwards + `riir-infer-gpu/src/gemma2_d2f/` CubeCL block-causal denoising loop) draws **per-position independent samples** each denoising step (`sample_with_confidence`, mask-token suppression) and commits by raw confidence (threshold, or the learned 7-param `DiffusionSampler`). Under any structured-output requirement (JSON schema, function-call grammar, format automaton) that is wrong twice: per-position draws do not respect joint constraints, and raw top-1 confidence over-commits on constraint-forced tokens. Mosaic (arXiv:2607.07026) provides the exact fix: FA-as-HMM forward–backward over the block trellis with the LM logits as emissions, **joint state-path sampling** (per-position marginals provably do not factorize the joint), O(log L) depth via a segment tree of pairwise log-space matrix products, composing with any commit/remask schedule because each step re-conditions on committed positions. Full math, complexity table, numerics traps (fp32 tree-product underflow at L=64 → fp64 escape hatch; NaN→uniform + deferred warnings), and the prior-art delta vs DINGO (2505.24061, exact but sequential/linear-depth) in `../.research/008_Mosaic_FA_Constrained_dLLM_Decoding.md`.

## Non-goals

- Not a trainer change — riir-train Plan 383 sibling trainers untouched.
- Not AR-side work — `katgpt-core::legal_token_set` already owns AR next-position legal sets; this is the mean-field/joint decode problem only.
- Not a default-on flip — the decode loop's default arm stays byte-identical; `fa_constraint` is opt-in until the GOAT gate passes (owner call at P3).
- No new external deps — pure std/core math in `riir-infer-core` (the repo's zero-katgpt-rs-dep posture holds; automaton tensors follow mosaic's CSR-style layout, not dense δ).

- [x] sequential sampler: node-level backward table `(len+1)×N` + forward ancestral draw over edge flow weights `e_log + back[dst]`; exact **joint** state-path-then-tokens sampling (tokens given the sampled edge: pinned take the pin, greedy = raw-logit argmax over the edge's tokens, else temperature multinomial) — `SplitMix64` internal RNG (seeded ⇒ reproducible, zero deps); `same_seed_same_logits_same_draw` pins it

### P2 — schema front end + bench — **COMPLETE 2026-10-06 (compiler `2788…` + bench this commit)**
- [x] JSON-schema → char-NFA → token-DFA compiler (type/properties/required/items/enum/anyOf, depth-bounded recursion — mosaic `grammar/json_schema.py` is the reference shape; tokenizer-trie re-alphabetisation for our vocab): `src/fa_schema.rs` (UNGATED core) — Thompson NFA → on-demand subset graph stepped by token chars (no alphabet table) → merged-edge `Automaton`; trailing-ws pad language = the block-padding mechanism; depth/NFA/subset/property caps as named errors. Three grammar-soundness laws found by the tests and pinned in-doc: (1) fresh ws wrappers — a shared star fragment's final carries every consumer's ε-exit and leaks across positions (`[42,]` walked an Integer array); (2) per-(mask,member) chains — a shared value fragment funnels all origin masks into one successor subset, so required-complete closes leaked into every path (`{"age":42}` accepted with `name` required); (3) acceptance = walk∧final, never walk alone
- [x] bench: per-step overhead vs unconstrained at L ∈ {64,128,256} × grammar scales (toy → function-call schema); box-state provenance per the G2 rule (`examples/fa_schema_overhead_bench.rs`, CPU-only — both arms run the SAME forwards, so the delta IS the sampling step): **toy-enum (14n/37e) 1.6-2.2×; object-2p (83n/316e) ~22× (0.29-1.3 ms/step); fn-call-5p (1473n/5997e) ~440-470× (5.7-27 ms/step)** — the joint draw is O(L·E) and E bloats with the 2^k·k member chains; the G2 single-digit-% bar needs automaton minimization and/or the GPU-side fold at P3
- [x] quality: grammar-following rate on a structured eval (synthetic first) — covered by the sampler round-trip gates: 200-seed joint draws through the REAL compiled object grammar are 100% walk-to-accepting (accepted by construction), and the pinned-prefix test completes a partial instance into ws padding; the real-model grammar-following eval rides the P3 GOAT gate (the GPU decode loop + a real tokenizer vocab)
